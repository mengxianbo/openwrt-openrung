## Source corresponding to a released client

For every IPK build, the build workflow records the exact packaging-repository commit and exact OpenRung upstream commit in the client IPK's `SOURCE-INFO.txt`.

The build artifact and the `openwrt-latest` GitHub Release contain:

1. `openwrt-openrung-source-<packaging-commit>.tar.gz` — exact packaging repository source, including the scripts used to assemble the IPKs.
2. `openrung-upstream-source-<upstream-commit>.tar.gz` — exact upstream source snapshot, including `go.mod`, `go.sum`, and upstream notices.
3. `openrung-upstream-corresponding-source-<upstream-commit>.tar.gz` — generated by the license-compliance workflow from that exact upstream snapshot. It adds the Go dependency source tree produced by `go mod vendor`, including `vendor/modules.txt` and license/notice files present in the vendored modules.

The third archive is uploaded as a separate artifact and attached to the same `openwrt-latest` release. Match its commit suffix to the client IPK's `SOURCE-INFO.txt`; do not substitute a newer source snapshot for an older binary.

## Limits of automated checks

The compliance workflow verifies license files, notices, commit identity, source archives, and the presence of vendored dependency source. It also checks that the client package resolves with the recorded vendored module tree and build tags.

These automated checks are not legal advice and do not replace a human review of each dependency's license, attribution, patent, trademark, or additional-term requirements. A passing workflow means the tested files and source bundle were present and internally matched; it is not a blanket legal certification.
